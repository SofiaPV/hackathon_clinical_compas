# Веб-слой «Медмонитора»

Flask-приложение поверх слоя данных `clinical_compass`. Полная инструкция по
установке и запуску — в корневом [`README.md`](../../README.md). Здесь собраны
технические примечания по самому веб-слою.

## Запуск (кратко)

Из корня проекта зависимости ставятся так:

```bash
python -m pip install -e .
python -m pip install -r src/web/requirements-web.txt
```

Затем задайте `SECRET_KEY` и запустите из каталога `src/web`:

```bash
export SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
python app.py        # http://127.0.0.1:5000
```

Таблицы и каталог тестов создаются автоматически при первом запуске.

## Примечания

- Регистрация создаёт запись пользователя и запись в `Doctors` или `Patients`
  в зависимости от флажка «Я врач»; при регистрации можно указать дату рождения.
- Сессия хранит только идентификатор, публичные данные пользователя и роль; роль
  определяется методом `SQLiteRepository.get_user_role`.
- Включена CSRF-защита форм.
- **Связь врач–пациент.** Врач создаёт QR-код (действует 5 минут, хранится как
  SHA-256, одноразовый). Пациент сканирует его камерой в приложении или штатной
  камерой телефона и подтверждает связь; она пишется в `Doctor_Has_Patient`.
- **Доступ врача.** У нового врача нет пациентов до подтверждения связи. Список,
  счётчики, профиль, статистика, просмотр ответов и проведение тестов доступны
  врачу только для связанных с ним пациентов — в том числе при обращении по
  прямым ссылкам.
- **Тесты.** Каталог задаётся в `TEST_DEFINITIONS` (`app.py`). Поле `audience`
  разделяет самостоятельные тесты пациента (`patient`: PHQ-9, GAD-7) и врачебные
  (`doctor`: HAM-A, C-SSRS, HAM-D). Результаты врачебных тестов пациенту не
  показываются. Расписание не накапливается: в каждый момент «висит» максимум
  одно прохождение теста.
- **Графики** рисуются самодостаточным SVG-рендером (`static/js/charts.js`),
  без внешних библиотек, поэтому работают офлайн в локальной сети.
- Работают дневник состояния, прохождение тестов и статистика. Переписка и
  назначение препаратов пока не подключены к интерфейсу.
- Чтобы сканирование с телефона работало, откройте приложение по LAN-адресу
  компьютера (не `localhost`); камера в браузере требует HTTPS или `localhost`.
- Не используйте встроенный сервер Flask и `debug=True` для публичного
  развёртывания. Для реальных медицинских данных нужны HTTPS, контроль доступа,
  резервное копирование и подтверждение роли врача.

## Статистика психологических тестов

В блоке «Динамика» в кабинете пациента отображаются графики пациентских тестов
(PHQ-9, GAD-7) за всё время, последние баллы и количество прохождений. Ссылка на
подробную статистику открывает историю и фильтр периода. Те же результаты
доступны врачу в детальной статистике пациента. Для каждого теста показаны
количество прохождений, последний результат, изменение относительно предыдущего
прохождения, график баллов и история с переходом к сохранённым ответам.

Фильтр «Неделя / 2 недели / Месяц / Всё время» применяется к дневнику и
статистике пациентских тестов. Последний результат и изменение считаются только
по прохождениям внутри выбранного периода. У каждого теста своя шкала,
вычисленная по вопросам; баллы разных тестов не объединяются. Врачебные тесты
остаются в отдельном верхнем блоке со всей историей.

Статистика доступна даже без записей дневника. Новые пациентские тесты из
каталога появляются в ней автоматически. Используются существующие результаты в
SQLite; миграция данных и внешние библиотеки графиков не нужны.

Интеграционные проверки выполняются из корня проекта на отдельной временной базе:

```bash
# macOS / Linux
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
```

```powershell
# Windows PowerShell
$env:PYTHONPATH="src"; .\.venv\Scripts\python.exe -m unittest discover -s tests -v
```
