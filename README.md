# Клинический компас / Медмонитор

Проект состоит из двух слоёв:

1. **Слой данных** (`src/clinical_compass`) — модели, интерфейс операций и
   SQLite-реализация. SQL-запросы изолированы в репозитории, поэтому поверх
   можно добавить любой бэкенд, не перенося SQL в обработчики.
2. **Веб-приложение «Медмонитор»** (`src/web`) — Flask-приложение для пациентов
   и врачей: дневник состояния, графики динамики, тесты по расписанию и кабинет
   врача с триажем пациентов.

> ⚠️ Прототип для разработки. Перед работой с реальными медицинскими данными
> нужны HTTPS, оценка безопасности, контроль доступа, резервное копирование и
> соответствие законодательству.

## Быстрый старт (с нуля)

С момента скачивания репозитория до работающего веб-приложения:

1. **Получите код.** Клонируйте репозиторий или распакуйте архив и перейдите
   в каталог проекта:

   ```bash
   git clone <url-репозитория> clinical_compass
   cd clinical_compass
   ```

   > Если распаковываете zip, собранный на macOS, удалите служебные файлы
   > `._*` и `.DS_Store` — они не нужны (`.gitignore` их уже игнорирует).

2. **Создайте виртуальную среду и установите зависимости.**

   Windows PowerShell:

   ```powershell
   py -3.12 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install --upgrade pip
   .\.venv\Scripts\python.exe -m pip install -e .
   .\.venv\Scripts\python.exe -m pip install -r src\web\requirements-web.txt
   ```

   macOS / Linux:

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   python -m pip install --upgrade pip
   python -m pip install -e .
   python -m pip install -r src/web/requirements-web.txt
   ```

3. **Запустите приложение** (ключ сессий + старт сервера).

   Windows PowerShell:

   ```powershell
   $env:SECRET_KEY = python -c "import secrets; print(secrets.token_hex(32))"
   cd src\web
   python app.py
   ```

   macOS / Linux:

   ```bash
   export SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
   cd src/web
   python app.py
   ```

4. Откройте `http://127.0.0.1:5000`. База данных, таблицы и каталог тестов
   создаются автоматически при первом запуске.

Подробности (переменные окружения, запуск только слоя данных) — в разделах ниже.

## Требования

- Python 3.10 или новее (разрабатывалось на 3.12).
- SQLite входит в стандартную библиотеку.

## Запуск веб-приложения

Нужен секретный ключ в переменной окружения `SECRET_KEY`.

### Windows PowerShell

```powershell
$env:SECRET_KEY = python -c "import secrets; print(secrets.token_hex(32))"
cd src\web
python app.py
```

### macOS / Linux

```bash
export SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
cd src/web
python app.py
```

Откройте `http://127.0.0.1:5000`. База данных и таблицы (включая каталог тестов)
создаются автоматически при первом запуске.

Полезные переменные окружения:

- `SECRET_KEY` — обязательный ключ подписи сессий.
- `CLINICAL_COMPASS_DATABASE` — путь к файлу БД (по умолчанию `../data/...`).
- `PUBLIC_BASE_URL` — адрес, который зашивается в QR-код для связи с врачом.
  Чтобы телефон смог открыть ссылку, укажите LAN-адрес компьютера
  (например, `http://192.168.1.10:5000`), а не `localhost`.
- `FLASK_DEBUG=1` — режим отладки (только для разработки).

> Встроенная камера для сканирования QR (`/scan`) работает только в защищённом
> контексте — по HTTPS или на `localhost`. По обычному HTTP в локальной сети
> браузер камеру не включит; запасной путь — сканировать QR штатной камерой
> телефона и перейти по ссылке.

## Возможности веб-приложения

- **Аккаунты и роли.** Регистрация и вход (email + PBKDF2-хеш пароля), роли
  «пациент» и «врач».
- **Связь врач–пациент по QR.** Врач генерирует одноразовый QR-код (живёт
  5 минут, хранится как SHA-256). Пациент сканирует его камерой прямо в
  приложении и подтверждает связь.
- **Дневник состояния пациента.** Три шкалы 0–10 (настроение, тревога, энергия)
  и необязательная заметка; лента заметок с текстом.
- **Динамика.** Превью-график на дашборде и страница расширенной статистики с
  выбором периода (неделя / 2 недели / месяц / всё время) и переключением
  активного показателя. Графики — самодостаточный SVG без внешних библиотек.
- **Тесты по расписанию (самостоятельные).** PHQ-9 и GAD-7 раз в две недели.
  Тест доступен сразу после регистрации и далее через интервал от последнего
  прохождения (без накопления). При наступлении срока на дашборде — баннер.
  Положительный ответ на критический пункт PHQ-9 показывает пациенту красный
  алерт, который исчезает после повторного прохождения с нулевым ответом.
- **Статистика пациентских тестов.** В «Динамике» пациента и в детальной
  статистике у врача по каждому тесту (PHQ-9, GAD-7) показаны количество
  прохождений, последний результат, изменение относительно предыдущего,
  график баллов и история с переходом к сохранённым ответам. Фильтр периода
  применяется и к этой статистике; баллы разных тестов не объединяются.
- **Кабинет врача.** Триаж пациентов, связанных с врачом (плитки «срочно /
  ухудшение / нет данных / стабильно» и таблица с сигналом, динамикой
  PHQ-9/GAD-7, средним настроением за 7 дней), профиль пациента, детальная
  статистика. Список, профиль, статистика и проведение тестов доступны врачу
  только для его пациентов — в том числе при переходе по прямым ссылкам.
- **Врачебные тесты.** HAM-A, C-SSRS (с ветвлением) и HAM-D проводит врач;
  результаты записываются пациенту, но пациенту недоступны — врач видит их в
  детальной статистике отдельными блоками.

Каталог тестов задаётся декларативно в `TEST_DEFINITIONS` (`src/web/app.py`):
новый тест добавляется одной записью с указанием аудитории (`patient`/`doctor`),
расписания, пороговых диапазонов и вопросов.

## Слой данных (библиотека)

`SQLiteRepository` реализует интерфейс `ClinicalCompassRepository`: создание
пользователей, врачей и пациентов, связывание врача с пациентом, дневник эмоций,
справочник препаратов, назначения, расписания и события приёма. Операции
возвращают типизированные объекты из `domain/models.py`, ошибки целостности
передаются как `sqlite3.IntegrityError`.

Пример использования:

```python
from datetime import date
from clinical_compass import SQLiteRepository

repository = SQLiteRepository("data/clinical_compass.sqlite3")
user = repository.create_user(name="Мария", surname="Иванова", password="…")
patient = repository.create_patient(user_id=user.id)
repository.create_emotion(user_id=patient.id, anxiety=3, mood=7, energy=5)
```

Запуск демонстрационного примера слоя данных:

```bash
python examples/basic_usage.py
```

## Важные решения и ограничения

- `Medication_Prescriptions.user_id` ссылается на `Patients.id`.
- `Doctors.id` и `Patients.id` одновременно являются внешними ключами на
  `Users.id`.
- Пароли хранятся как соль + PBKDF2-HMAC-SHA256.
- Оценки тревожности, настроения и энергии валидируются в диапазоне 0–10
  (`_validate_scale`).
- Врачебный доступ проверяется на каждом маршруте кабинета врача; результаты
  врачебных тестов не отдаются пациенту.
- Флажок «Я врач» при регистрации пока открыт для всех — для реального сервиса
  роль врача нужно подтверждать отдельно.

## Подключение другого бэкенда

Обработчики должны зависеть от `ClinicalCompassRepository`, а не от
`SQLiteRepository` напрямую. Для перехода, например, на PostgreSQL добавьте
другую реализацию интерфейса, сохранив модели и контракт операций.
